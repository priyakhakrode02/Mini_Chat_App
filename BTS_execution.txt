Understanding the Two Delete Buttons: 


My Application has two delete buttons, and each one triggers a different process: 
1️⃣ Delete button in index.ejs → Takes the user to a confirmation page (delete.ejs). 
2️⃣ Delete button in delete.ejs → Actually deletes the chat from the database.

📌 Step-by-Step Execution of Your Code
Step 1: User Clicks the First Delete Button (in index.ejs)
🔹 What the User Sees:

The user is on the index page, which lists multiple chats.
Each chat has a Delete button:


<form method="post" action="/chats/<%= chat._id %>?_method=DELETE">
    <button name="delete">Delete</button>   
</form>

When the user clicks this button, the form sends a request to:

/chats/680f3c31ec83d946527233b8?_method=DELETE

680f3c31ec83d946527233b8 is the _id of the chat the user wants to delete.
_method=DELETE is added because HTML forms don’t support DELETE requests by default. 
🟢 We use method-override to change a POST request into a DELETE request.

Step 2: Express Handles the Request and Redirects to the Delete Confirmation Page

Your server (index.js) has this route:

app.get("/chats/:id/delete", async (req, res) => {
    let { id } = req.params; 
    let chat = await Chat.findById(id); // Chat.findById(680f3c31ec83d946527233b8)
    res.render("delete.ejs", { chat }); // delete.ejs html will displays data for this particular id only
});

id   = 680f3c31ec83d946527233b8
chat = {
        "_id": "680f3c31ec83d946527233b8",
        "from": "bubbu",
        "to": "duddu",
        "msg": "I am sorry duddu",
        "created_at": "2025-04-28T08:28:33.074Z"
        }


🔹 What Happens in the Background?
 1️⃣ Express extracts the id from the URL (req.params.id).
 2️⃣ MongoDB searches for the chat using Chat.findById(id).
 3️⃣ Express passes the chat data to delete.ejs. 
 4️⃣ EJS displays the chat details dynamically on the delete confirmation page.

 Step 3: User Sees the Delete Confirmation Page (delete.ejs)

 What the User Sees:
The confirmation page (delete.ejs) asks: 🟢 "Are you sure you want to delete this chat?"

It shows the chat details using EJS:
HTML

<p><b>Chat Id: <%= chat._id %> </b></p>
<p>From: <%= chat.from %></p>
<p>Message: <%= chat.msg %></p>
<p>Received By: <%= chat.to %></p>

The user sees:

Are you sure you want to delete this chat?

Chat ID: 680f3c31ec83d946527233b8
From: bubbu
Message: "I am sorry duddu"
Received By: duddu

There is a second delete button:

<form method="post" action="/chats/<%= chat._id %>?_method=DELETE">
    <button class="del-btn">Delete</button>
</form>


Step 4: User Clicks the Second Delete Button (in delete.ejs)

🔹 What Happens Next?
     The second Delete button sends a DELETE request to:
        /chats/680f3c31ec83d946527233b8?_method=DELETE

Now, your server needs to handle this DELETE request.

Step 5: Express Handles the Actual Delete Request

🔹 Your DELETE Route in index.js:

app.delete("/chats/:id", async (req, res) => {
    console.log("Received DELETE request for:", req.params.id);

    let { id } = req.params; 
    let deleteChat = await Chat.findByIdAndDelete(id); 

    console.log(deleteChat);
    res.redirect("/chats");
});

What Happens in the Background?

1️⃣ Express extracts the id from the URL (req.params.id).
2️⃣ MongoDB deletes the chat using Chat.findByIdAndDelete(id).
3️⃣ Express logs the deleted chat (for debugging).
4️⃣ Express redirects the user back to /chats, so they see the updated list.

Step 6: The User Returns to the Chats Page

🔹 Final Outcome

The chat has been deleted from the database.

The user is redirected back to /chats, which no longer shows the deleted chat.

Now, when the page reloads, the chat list does not include the deleted chat.

🔁Complete Flow of Execution

1️⃣ User clicks "Delete" on index.ejs → Redirected to /chats/:id/delete.
2️⃣ Server finds the chat (findById) and sends data to delete.ejs → User sees chat details.
3️⃣ User clicks "Delete" on delete.ejs → Sends DELETE request to /chats/:id. 
4️⃣ Server deletes the chat (findByIdAndDelete) and redirects back to /chats. 
5️⃣ User returns to /chats, and the chat is gone!
